## What was done, and what it showed

1. **Live model fixes** (`examples/live-fixes/`). No model CLI was logged in on the build hosts ("Not logged in"), so `providers/cli-provider.sh` could not run; **the model was the assistant that built this slice, a model**, answering from the request text the loop built (prompt + 31-line code window), then replayed in the jail.
   Three findings on three files: libev `ev.c` (EVENTFD), dropbear `src/svr-main.c` (PRCTL), iperf `src/net.c` (SENDFILE). Each project was configured with the SDP's qcc first (otherwise every compile stops at `config.h`). Result, honestly: **libev: qcc pass 0 -> 0, but the patch changes nothing the compiler sees** (libev's configure had already switched eventfd off);
   **dropbear: no-worse 4 -> 4**, **iperf: no-worse 1 -> 1**: both files already fail on qcc before the patch (dropbear `compat.h` redeclares `htole64` & co. which QNX defines as macros; iperf `portable_endian.h` includes the absent `<endian.h>`), so the check cannot judge the patch beyond "added no error".
   The model marked the iperf reply `needsHuman: true`. No token usage recorded (a session reply has no usage frame).
   The empty `provider exit 1:` is fixed: the failure text now comes from stdout and stderr (the CLI reports login errors on stdout) plus a hint; also fixed an EPIPE race for providers that exit without reading stdin. Tested.
2. **Build-file checks.** `--check qcc` now covers Makefile/`*.mk` (`make -n` with `CC=qcc -V...`, then a real `qcc` link probe for every `-l` library the dry run names) and CMake (`cmake` configure with the generated `qnx-toolchain.cmake`, then the same probe on `link.txt`). `check=skipped` is gone for these in the qcc mode.
   Real runs in the jail: demo-epoll Makefile patch **pass 1 -> 0**; demo Makefile: the first patch `no-worse` (still `-lrt`), the `-lrt` removal **pass 1 -> 0**; a CMake project with `rt` fails on both targets with `cannot find -lrt` (`examples/build-check-output.txt`). Without `--check qcc` (host gcc) build files are still `skipped`. New `--qcc-flags` option adds include paths/defines.
3. **QEMU run: not done, documented** (`examples/qnx-run/README.md`). In the sandbox `mkqnximage --type=qemu --arch=x86_64 --build` **succeeded** (150 MB disk, 10.9 MB IFS) with the patched demo server (built by qcc) and a client added and a boot script appended; `mkqnximage --run` stops with `Can't find qemu-system-x86_64, perhaps you need to install QEMU.` No `/dev/kvm` either. Ops needs the `qemu-system-x86` package visible to the sandbox (not installed here: it is a change outside the repo on a shared host). `bash tools/qnx-run.sh` then does the boot. **Nothing was run on QNX.**
4. **Report UX.** *Where* strip (top 6 files/dirs, clickable) and a verified/known/guess bar above the fold at 1440x900 (screenshot checked in headless Chrome); the old confidence card removed; "1/1 site" grammar; remedy text cut at a word boundary; rule count reconciled (README 61 = `portdoctor rules`); `examples/README.md` counts fixed (5 without the manifest, 3 with it). **The bundled manifest is the default**; `--no-sdp-manifest` switches it off; `package.json` files now include the manifest.

This is a literal path match standing in for a judgement; it is marked a bridge in `src/scan.ts` (`HIDE_RULES`, target 2026-12-15, replacement = a model judge that reads the file). **Held-out sample** (40 findings not in PD1/PD2, `corpus/sample40.mjs`, `corpus/precision-sample-pd4.txt`, `corpus/PRECISION.md`): rule did what it says **35/40 = 87.5%**, rule bugs **0/40**, irrelevant **5/40 = 12.5%**, plain actionable TP **1/40 = 2.5%** (PD2: 7%: no improvement there). One reader, the author: not independent. The hidden findings were not re-read.
6. **Rules and remedies.** New rules (61 total): `QNX-HDR-ENDIAN`, `QNX-API-BSWAP`, `QNX-API-BYTEORDER` (`#if __BYTE_ORDER == __LITTLE_ENDIAN` is silently true on QNX: both sides evaluate to 0), `QNX-API-POLLRDHUP`, `QNX-API-RTSIG` (info: SIGRTMIN/SIGRTMAX exist). Manifest regenerated in the jail with 30 more names (no existing verdict changed): htole/htobe macros are in `<net/netbyte.h>`; `endian.h`, `sys/endian.h`, `byteswap.h`, `bswap_N`, `__BYTE_ORDER`, `PR_SET_NO_NEW_PRIVS`, `POLLRDHUP` absent; `procmgr_ability` and `PROCMGR_*`, `DCMD_PROC_MAPINFO`, `<gulliver.h>` ENDIAN_* present.

The iperf endian break the live check hit is now found by the scan (`QNX-HDR-ENDIAN`, verified-absent).
