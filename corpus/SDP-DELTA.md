## Frank assessment (written by hand, from the numbers above and the manifest)

- **Wrong in PD2, now corrected by evidence:** (1) `QNX-API-INOTIFY` said no QNX equivalent was known and listed it as a blocker: inotify exists (`<sys/inotify.h>`, libfsnotify, needs `-lfsnotify`). (2) The epoll remedy pointed at kqueue/kevent via io-sock: the SDP ships no user-facing `<sys/event.h>` and no library exports `kqueue`, so that advice was wrong. (3) The gettid remedy ("pthread_self is not a replacement") was right but incomplete: `gettid()` exists natively in `<sys/process.h>`. (4) `pthread_getattr_np` "may exist": it does not. (5) `QNX-HDR-SYS-LINUX` listed `sys/inotify.h` and `sys/auxv.h` as absent headers: both exist. (6) `accept4`, `pipe2`, `SOCK_NONBLOCK/CLOEXEC`, `MSG_NOSIGNAL`, `TCP_FASTOPEN`, `TCP_INFO`, `SO_REUSEPORT` were flagged (hedged) as maybe-missing: all are defined; accept4 needs `-lsocket`; `dup3` is the one that is really missing.
- **Right in PD2 and now confirmed:** epoll/eventfd/timerfd/signalfd, the `<linux/...>` headers, prctl, getrandom, sched_setaffinity, mremap, SysV IPC, O_PATH/O_DIRECT, the Linux-only clock ids and TCP_CORK-style options, and -lrt/-lpthread/-ldl/-lnsl/-lutil/-lresolv (none of these libraries exist).
- **Missed by PD2:** socket code needs `-lsocket` on QNX 8.0 (`socket`, `bind`, `accept`, `getaddrinfo`, ... are undefined references without it): found by a real link in PD3, then added as rule `QNX-BLD-LSOCKET`. `SA_RESTART` is commented out in `<signal.h>` ("not supported yet"), `IOV_MAX` and `HOST_NAME_MAX` are not user-visible, and `sendfile` is declared but not exported; the scanner has no rule for those.
- **What the SDP cannot decide here:** about half of the findings (`#ifdef` advice, `/proc` and `/sys` paths, device nodes, uname/compiler hard-coding, project-level build rules). Their labels are unchanged (known/guess).
- **Limits of this evidence:** one SDP build, compile/link/symbol probes only, nothing run on a target; a probe passes when the name is visible and links, which says nothing about behaviour (for example whether inotify on QNX has the same semantics). The probe includes a fixed set of common POSIX headers, so a name that needs an unusual header can be reported absent; that is why the manifest keeps the compiler error for every absent name. 13 findings were dropped as "present"; treat that as "not reported", and use `--sdp-keep-present` to see them.
